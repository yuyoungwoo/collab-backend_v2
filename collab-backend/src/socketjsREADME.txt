[ socket.js ]

코드 리뷰 에디터의 핵심인 "실시간" 기능
한 명이 코드를 입력하면 같은 공간(룸)에 있는 모든 사람 화면에 바로 반영되는 기능을 처리

일반 HTTP 통신은 "클라이언트가 요청해야만 서버가 응답"을 함,
하지만 실시간 기능은 "서버가 클라이언트에게 먼저 데이터를 밀어넣을" 수 있어야 가능함.
이걸 가능하게 하는게 WebSocket과 Socket.io임



[ 핵심 용어 설명 ]

▶ WebSocket
   - HTTP와 다른 통신 방식
   - HTTP: 클라이언트 요청 → 서버 응답 (단방향, 매번 새 연결)
   - WebSocket: 한 번 연결하면 양방향으로 자유롭게 통신 (지속 연결)
   - 쉽게 말하면: HTTP는 편지, WebSocket은 전화통화

▶ Socket.io
   - WebSocket을 더 쉽게 쓸 수 있게 만든 라이브러리
   - 자동 재연결, Room 관리, 이벤트 기반 통신 등 편의 기능 제공

▶ Room (룸)
   - Socket.io의 그룹 개념
   - 쉽게 말하면: "채팅방"처럼 특정 그룹에게만 메시지를 보낼 수 있음
   - 우리는 세션 ID를 룸 ID로 사용
   - socket.join('룸ID') = 룸 입장
   - io.to('룸ID').emit(...) = 그 룸의 모든 사람에게 전송
   - socket.to('룸ID').emit(...) = 나를 제외한 룸의 모든 사람에게 전송

▶ emit (이미트)
   - 이벤트를 보내는 것
   - socket.emit('이벤트명', 데이터) = 서버 → 특정 클라이언트에게 전송
   - io.to('룸').emit('이벤트명', 데이터) = 서버 → 룸 전체에게 전송

▶ on (온)
   - 이벤트를 받아서 처리하는 것
   - socket.on('이벤트명', 처리함수) = 이 이벤트 왔을 때 실행할 함수 등록

▶ Map (맵)
   - JavaScript의 key-value 저장 구조
   - 쉽게 말하면: 사물함처럼 key(번호)로 value(내용물)를 저장/조회
   - rooms Map: 룸ID → 참여자 목록
   - userSockets Map: 유저ID → 소켓ID

▶ Set (셋)
   - 중복 없는 값들의 모음
   - 배열과 비슷하지만 같은 값이 들어올 수 없음
   - 참여자 목록을 Set으로 관리해서 중복 입장 방지

▶ handshake (핸드쉐이크)
   - 연결을 맺는 초기 과정
   - socket.handshake.auth = 연결 시 클라이언트가 보낸 인증 정보
   - 프론트에서 io({auth: {token: 'JWT토큰'}}) 형태로 전달



[ 코드 흐름 ]

[연결 시]
1. io.use 미들웨어: JWT 토큰 검증 (실패 시 연결 거부)
2. connection 이벤트: 연결 성공 시 유저 정보 등록

[에디터 입장 시 - join-room 이벤트]
1. Socket.io 룸에 입장 (socket.join)
2. 참여자 Map에 유저 추가
3. 룸 전체에 최신 참여자 목록 전송

[코드 입력 시 - code-change 이벤트]
1. DB에서 이 세션의 오너인지 확인
2. 오너가 아니면 권한 테이블 확인
3. 권한 없으면 permission-denied 이벤트 전송 후 종료
4. 권한 있으면 룸의 다른 사람들에게 코드 전송
5. DB에 최신 코드 저장

[연결 끊김 시 - disconnect 이벤트]
1. userSockets Map에서 제거
2. 모든 룸의 참여자 목록에서 제거
3. 변경된 참여자 목록 브로드캐스트



[ 이 파일에서 사용하는 라이브러리 ]

▶ jsonwebtoken (jwt)
   - 소켓 연결 시 토큰을 검증하기 위해 사용

▶ Socket.io (Server)
   - index.js에서 생성된 io 객체를 받아서 이벤트 등록
   - io.on(), socket.on(), socket.emit(), io.to().emit() 등 사용
