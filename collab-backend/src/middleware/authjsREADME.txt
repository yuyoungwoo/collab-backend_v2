[ authjs.js ]

현재 만들고 있는 웹 페이지는 로그인 후 가능한 기능들로 구성됨.
예를 들어 세션 목록 보기, 댓글 달기, 스니펫 저장 등등...

그런데 이 기능마다 "로그인했는지 확인하는 코드"를 일일이 붙이면
코드가 엄청 길어지고 중복이 많아져 쓸대없이 무거워짐

그래서 이 검사 기능을 "미들웨어(Middleware)"라는 개념으로 따로 만듬.
미들웨어란? → 요청이 들어오면 실제 처리 전에 중간에서 먼저 실행되는 검사기
쉽게 말해 "중간 검사관"

auth.js 미들웨어를 API 앞에 붙이면, 토큰 없는 사람은 자동으로 막힘



[ 핵심 용어 설명 ]

▶ JWT (JSON Web Token)
   - 풀네임: JSON Web Token
   - 뜻: JSON 형식으로 만든 웹 토큰
   - 쉽게 말하면: "로그인 증명서" 또는 "디지털 출입증" 이에요.
   - 예시: 놀이공원 입장권처럼, 한 번 발급받으면 계속 들고 다니며 사용함.
   - 구조: 헤더.페이로드.서명 이렇게 점(.)으로 3부분으로 나뉨
     예) eyJhbGci.eyJ1c2Vy.SflKx... ← 이렇게 생긴 긴 문자열
   - 왜 쓰나: 서버가 매번 DB에서 로그인 여부를 확인하지 않아도 됨.
              토큰 자체에 유저 정보가 들어있어서 빠름.

▶ Middleware (미들웨어)
   - 뜻: 요청과 응답 사이에서 중간에 실행되는 함수
   - 쉽게 말하면: "중간 검사기" 또는 "게이트키퍼"
   - 예시: 클럽 입구에서 나이를 확인하는 경비원처럼,
          API 요청이 실제 처리되기 전에 먼저 실행돼서 조건을 검사함.

▶ Authorization (인가/권한)
   - 뜻: 이 사람이 이 기능을 쓸 권한이 있는지 확인하는 것
   - 쉽게 말하면: "출입증" 확인
   - 요청 헤더에 "Authorization: Bearer 토큰값" 형태로 보냄.
   - Bearer: "이 토큰을 가진 사람" 이라는 뜻의 접두사

▶ req (Request, 요청)
   - 클라이언트(브라우저)가 서버에 보내는 요청 정보 전체
   - req.headers → 요청 헤더 (토큰이 여기 담겨옴)
   - req.user → 우리가 직접 추가하는 필드 (토큰에서 꺼낸 유저 정보)

▶ res (Response, 응답)
   - 서버가 클라이언트에게 돌려주는 응답 객체
   - res.status(401) → HTTP 상태코드 401 (인증 실패) 설정
   - res.json({}) → JSON 형태로 응답 전송

▶ next
   - 다음 미들웨어 또는 실제 라우트 핸들러로 넘어가는 함수
   - next()를 호출해야 다음 단계로 진행됨
   - 호출 안 하면 요청이 거기서 멈춤

▶ HTTP 상태코드
   - 200: 성공
   - 201: 생성 성공
   - 400: 잘못된 요청 (클라이언트 실수)
   - 401: 인증 실패 (로그인 안 됨)
   - 403: 권한 없음 (로그인은 됐지만 이 기능은 못 씀)
   - 500: 서버 내부 오류



[ 코드 흐름 ]

1. 요청이 들어옴
2. 요청 헤더에서 Authorization 값을 꺼냄
3. 값이 없거나 "Bearer "로 시작 안 하면 → 401 에러 반환, 종료
4. "Bearer 토큰값"에서 실제 토큰값만 분리
5. jwt.verify()로 토큰이 진짜인지 검증
6. 진짜면 → req.user에 유저 정보 저장 후 next() 호출 (다음으로 진행)
7. 가짜/만료면 → 401 에러 반환, 종료



[ 이 파일에서 사용하는 라이브러리 ]

▶ jsonwebtoken (jwt)
   - npm 패키지명: jsonwebtoken
   - 설치: npm install jsonwebtoken
   - 역할: JWT 토큰을 만들고(sign), 검증(verify)하는 도구
   - jwt.verify(토큰, 시크릿키) → 토큰이 진짜인지 확인하고 내용을 꺼냄
   - 왜 시크릿키가 필요한가: 토큰이 위조/변조되지 않았는지 확인하기 위해
                           서버만 아는 비밀 키로 서명했기 때문에 위조 불가능
